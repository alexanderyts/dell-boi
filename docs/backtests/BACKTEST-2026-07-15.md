  120 host links total

  links)

  rack-driven sizing behavior)

### Maintainer judgment calls — MUST be signed off before pinning
(the correct counts flow from these; marked ☐ until decided)

- ☑ J1 DECIDED (2026-07-16, maintainer): "Fully redundant (dual)"
  means dual-homed hosts into a redundant leaf PAIR on ONE fabric —
  VLT on OS10, MC-LAG on Enterprise SONiC (OS-appropriate term must
  appear on the BOM/ICL line). NOT two air-gapped fabrics. Fixture A
  is built on this basis.
- ☑ J2 DECIDED (2026-07-16, maintainer): NOT a fixed policy — it
  varies per customer request. The tool must support quoting BOTH:
  (a) new spine tier (self-contained pod), and (b) spine-less —
  leaves uplink directly to the customer's existing core.
  IMPLEMENTATION CONSEQUENCE: this requires a wizard/expert input
  (e.g. "uplink target: new spine / existing core") wired into
  sizing — it must pass the input-effect invariant, not be a label.
  FIXTURE CONSEQUENCE: Fixture A below pins variant (a) with-spine;
  a Fixture A2 (spine-less: no S5232F line, no leaf→spine AOCs,
  leaf uplinks go directly to core handoff) must be added when the
  input exists. Same applies to Fixture B's spine question.
- ☑ J3 DECIDED (2026-07-16, maintainer): "Our side only" is the
  DEFAULT, not the ceiling — the tool must be able to accommodate the
  customer's core when asked. IMPLEMENTATION CONSEQUENCE: an input
  (e.g. "core handoff: our side only / include far side") wired into
  sizing. When far side is included, the wizard needs the customer's
  core port details (media/speed/connector — or "unknown", which
  quotes matched optics with a verify flag) and the BOM adds the
  far-side transceivers (matched to ours: same standard, 2 per link
  total becomes 2 per SIDE per link... i.e., 1 transceiver per port,
  both ports quoted) and any far-side patch cords. When "our side
  only" (default), the existing behavior stands: our transceivers +
  cords, far side by others, stated on the line. Must pass the
  input-effect invariant like J2's input. FIXTURE CONSEQUENCE:
  Fixtures A/B keep the our-side-only handoff lines as the default
  variant; a far-side-included variant fixture is added when the
  input exists.

### Invariants both fixtures must satisfy (Phase 1 tests)
1. Every line qty derivable from its own fields (links × units-per-link
   or per-rack × racks).
2. Every model referenced in any note appears as a switch line.
3. RJ45 lines carry zero DAC/SFP/optic metadata.
4. Dual and single fixtures MUST differ in hardware, not just labels.
5. Redundant leaf pairs include an interconnect line (VLT ICL on
   OS10 / MC-LAG peer link on SONiC — terminology matches the
   design's OS); non-redundant designs include none.
6. (Per J2) The uplink-target input ("new spine" vs "existing core")
   must change the hardware: with-spine variants include spine
   switch lines + leaf→spine cables; spine-less variants include
   neither, and leaf uplinks terminate at the core handoff. Both
   variants must pass invariants 1–5.
7. (Per J3) The core-handoff input ("our side only" vs "include far
   side") must change the hardware: our-side-only quotes our
   transceivers/cords with "far side by others" stated; far-side-
   included adds matched far-side transceivers (verify-flagged if
   core port details unknown) and far-side cords. Both variants must
   pass invariants 1–5.

### Fixture corrections caught by the build (falsification discipline)

When implementing a defect fix, the build re-derives the fixture from
the real engine + design rules and can FALSIFY a hand-authored fixture
number. When it does, the FIXTURE is corrected to the design (not the
engine bent to a wrong fixture), and the reasoning is logged here.

- **Error #1 — Fixture A/B OOB self-mgmt (66, not 68).** The hand
  drafts assumed the tool self-counts the OOB switches' own mgmt ports.
  It doesn't (engine sums `category==='Switch'` only): dual = 60 hosts
  + 4 leaf + 2 spine = 66. Ruling 2026-07-16: OOB switches are managed
  via console/in-band, not self-cabled. (Corrected during Phase 1.)

- **Error #2 — Fixture B single-fabric shape (B4/B6 increment,
  2026-07-16).** Two hand-authored numbers were falsified by the build:
  1. **Host cabling 120 → 60.** The draft pinned leaf=2 AND host=120,
     but 2× 48-port S4348T-ON = 96 ports < 120 — physically impossible.
     Maintainer ruling: a NON-redundant design is SINGLE-HOMED — each
     host uses ONE of its two NIC ports (the other spare), so 60 links
     on 2 leaves (30/leaf, 63% util). The host-cable note states it:
     "…(1/unit × 60; 1 NIC port spare — non-redundant (single-homed)
     design)".
  2. **Spine 1 → 0, mgmtcable 63 → 62.** The draft pinned a
     non-redundant spine "for growth." But a 2-leaf design falls under
     the engine's own >2-leaves-→-spine rule AND the backtest's own
     stated preference ("prefer direct routed uplink to existing core,
     no new spine tier"). Maintainer ruling: Fixture B is the
     spine-less / direct-to-core variant — the leaves are the
     border-leaf to the customer's existing core. So no S5232F, no
     leaf→spine AOC, mgmtcable = 60 hosts + 2 leaf = 62. The growth-
     spine is J2's `uplinkTarget: 'new-spine'` opt-in when it lands.
  Fixture B now pins: 2× S4348T-ON, 60× Cat6A, no spine, direct-to-core
  (2× 100G transceiver + 4 LC cords), 2× OOB, mgmtcable 62, no ICL, no
  pair language. Fixture A (dual) is unchanged in intent and now passes
  with the 4× 100G DAC ICL (VLT/MC-LAG per J1) the engine was missing.
