Introduction
This chapter presents the following topics:
Business Challenge
The landscape of Artificial Intelligence (AI) is becoming the hottest segment in the technology industry. It is undergoing rapid evolution and is becoming increasingly indispensable for businesses looking to gain a competitive foothold and stay competitive. Deploying AI solutions is a complex endeavor. The intricacies of developing and overseeing the sophisticated architectures that support AI algorithms and models pose challenges, especially for organizations lacking the necessary expertise and time to craft, implement, and manage a comprehensive AI solution stack. The scalability of AI applications is crucial for handling vast datasets and accommodating increased user demands. Maintaining optimal performance without the appropriate infrastructure and surrounding ecosystem poses difficulties for enterprises. AI workloads tend to be resource-intensive, and high-performance and lossless data contribute to the elevated infrastructure and operational cost. Therefore, it becomes crucial to streamline, manage, and scale resource utilization to minimize cost while ensuring operational efficiency. Having clear visibility into a proven AI solution stack becomes the first hurdle for any organization looking to implement an AI solution. Dell Technologies provides several AI solution stacks consisting of networking, compute, storage, and application components.
Solution introduction
This design guide describes the software and hardware components as well as the processes required to build a Dell Technologies AI environment. Dell Enterprise Software for Open Networking in the Cloud (SONiC) powers the deployment of two different topologies: standalone and leaf-and-spine. The two different topologies discuss the different fabrics that support the deployment environment of a typical AI workload: ● Out-of-Band (OOB) management fabric – This fabric supports the overall environment management network for the
solution. ● Front-end fabric – This fabric supports the deployment of storage, application, and in-band cluster management
components of the AI solution. ● Scale-out fabric – This fabric supports an actual AI GPU interconnect network. This networking design guide uses the Dell PowerSwitch Z-series product family for the fabric elements. The Z9864F-ON, Z9664F-ON, and Z9432F-ON are 800GbE/400GbE based platforms that run Dell Enterprise SONiC. The storage element of the solution is provided by Dell PowerScale platform.
Document purpose
The purpose of this document is to provide general networking configuration guidance for greenfield deployment of AI single and multi-cluster GPUs using a Dell Technologies product portfolio (PowerSwitch, PowerEdge, PowerScale, and Enterprise SONiC 4.2.1 or later).

Overview of AI fabrics: OOB, scale-out, and front-end
OOB management fabric
The OOB fabric provides local or remote management connectivity into the AI infrastructure. The OOB management fabric bandwidth is usually set to 1GbE. The OOB connections range from simple iDRAC connections from the PowerEdge XE9680 and PowerScale appliances, to RJ45 Ethernet management ports on the PowerSwitches. The OOB fabric is assigned to a single subnet or VLAN. The default VLAN is 1, however, most customers use a different VLAN ID. This VLAN is then routed across the network so that it is reachable from anywhere. The AI OOB fabric uses the PowerSwitch S3248T-ON. This switch supports Layer 2 and Layer 3 switching, and the switchport speeds are 1GbE. The Dell PowerSwitch S3248T-ON (formerly known as N3248TE) has four 10GbE SFP ports that can be used to uplink onto the legacy or existing network. The following figure shows the OOB connections from all the devices in the Dell AI environment. Each PowerScale or ECS appliance has a single OOB connection to the Dell PowerSwitch S3248T-ON.

Scale-out GPU fabric
The scale-out GPU fabric is referred to as the inter-GPU fabric. From the three different fabrics, the scale-out GPU fabric is the most bandwidth intensive and requires careful planning. There are two types of scale-out topologies: ● Pure rail ● Rail optimized
Pure rail
The following figure shows a pure rail topology where each Dell PowerSwitch provides dedicated connectivity to a set of GPUs. A blue rail switch provides connectivity for all blue GPUs. The same applies for orange GPUs and the other GPUs. The connections from the Dell PowerEdge XE9680 to the Dell PowerSwitch Z9864F-ON/Z9664F-ON can be 800GbE/400GbE respectively. The connections from GPU to switch are configured using Layer 3 networking. Each connection is a point-to-point Layer 3 with a /31 subnet IP address. For example, GPU blue from Node_1 would be configured with an IP address 192.168.1.1/31 and the switchport interface would be configured with an IP 192.168.1.0/31.

14

Dell Technologies AI Fabrics Architecture Overview

Figure 12. Pure rail scale-out GPU fabric
In a pure rail topology, three different GPU communication paths can take place: ● Path #1 – If GPU blue wants to communicate with another GPU blue, the common rail switch onto which both blue GPUs
are connected will be used. ● Path #2 – If GPU blue wants to communicate with GPU orange in Node_1, then an internal link in Node_1 is used. ● Path #3 – If GPU blue in Node_1 wants to communicate with GPU orange in Node_N, then GPU blue will send its data to
a local GPU orange in Node_1, then GPU orange will forward the data upstream to its dedicated rail switch, and finally the data is sent downstream to the directly connected GPU orange in Node_N.

Front-end fabric (storage, application, in-band management)
The front-end GPU fabric is dedicated for AI storage, application, and in-band GPU resources management support. AI storage is needed as large datasets are ingested, fine-tuned, trained, and inferred-on.

The application part is the GPU cluster management service using Slurm, or Kubernetes. These GPU management cluster software stacks provide a single pane of glass to manage GPU cluster service and management.
This fabric is not as bandwidth intensive as the scale-out GPU fabric. At 200GbE or 100GbE, storage, application, and in-band management access to and from the GPU fabric cluster is sufficient.
NOTE: Unlike the scale-out fabric where 400GbE is deployed, the front-end fabric can use 200GbE, 100GbE, 40GbE, 50GbE, 25GbE. For AI however, 200GbE or 100GbE is recommended to accommodate the amount of traffic between the GPU cluster and storage needs.
GPU storage, application, and in-band GPU cluster management speeds are configured at 200GbE, 25GbE, and 25GbE respectively from the Dell PowerSwitch to PowerScale, application, and in-band GPU cluster server (see Figure 17 and Figure 18).

Figure 17. Single front-end Dell AI GPU storage, application, GPU management topology
The Dell PowerSwitch providing the front-end fabric is configured as a Layer 2 switch with three different VLAN segments (storage, application, and in-band GPU management cluster)
The connection from the storage, application, and in-band cluster management to the Dell PowerSwitch is Layer 2 and these connections are configured as link-aggregation (LAG) bundles providing link redundancy upon a link failure.
The PowerScale cluster has two fabrics, one for inter-PowerScale appliance connectivity, and a second fabric for front-end for storage to GPU communication. In this networking guide, only the front-end fabric infrastructure configuration is covered.
The inter-PowerScale fabric uses both Ethernet or InfiniBand, and it is NOT user configurable. This fabric comes pre-configured or deployed from the manufacturing floor.
For GPU cluster management, Slurm or Kubernetes is deployed on 2-node PowerEdge cluster and for in-band cluster management such as scheduling GPU jobs, another set of 2-node PowerEdge cluster is used.
Each of these services (storage, application, and in-band GPU cluster management) is assigned a unique VLAN ID or subnet.
Due to the size of the front-end fabric (single or redundant switches), basic inter-VLAN routing with BGP as the routing protocol is used for these different VLANs to communicate with the outside world through the uplinks that are connected to the external network.
