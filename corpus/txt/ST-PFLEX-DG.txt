Dell Technologies' vision
The vision at Dell Technologies is to be the essential technology company for the data era. Dell Technologies ensures modernization for today's applications and the emerging cloud-native world. Our Networking team is committed to disrupting the market with an open strategy that gives you the freedom of choice for networking operating systems and top-tier merchant silicon. The Dell Technologies strategy enables business transformations that maximize the benefits of collaborative software and standards-based hardware, including lowered costs, flexibility, freedom, and security. Dell Technologies provides further customer enablement through validated deployment guides that demonstrate these benefits while maintaining a high standard of quality, consistency, and support.
Dell Technologies Enterprise SONiC
SONiC is an open-source, Linux-based network operating system (NOS) that runs on switches from multiple vendors and ASICs. Dell Technologies Enterprise SONiC is a hardened and validated version of SONiC supported on selected Dell PowerSwitch platforms. Dell Technologies Enterprise SONiC supports an intuitive command-line interface, object-based administration through a REST interface, and Google's gRPC Network Management Interface (gNMI).
PowerFlex
PowerFlex is a highly scalable compute and storage infrastructure that integrates PowerFlex software-defined storage software with Dell PowerEdge servers. PowerFlex supports a small cluster starting point of four nodes, bring-your-own networking hardware, and bring-your-own management hardware. PowerFlex allows growth and management of compute and storage resources together or independently depending on business needs. PowerFlex uses PowerFlex Manager for management and operations. PowerFlex Manager enables users to build, automate, and simplify implementation, expansion, and life cycle management.
Document purpose
This guide covers Dell Technologies Enterprise SONiC PowerSwitch configuration for single or multirack PowerFlex deployments. This deployment uses PowerFlex partial network automation (PNA). With PNA, PowerFlex Manager automatically configures the VLANs and IP addresses on the PowerFlex nodes. Dell PowerSwitch network switches running Enterprise SONiC are configured manually.
NOTE: PowerFlex full network automation (FNA) is not supported with Dell Technologies Enterprise SONiC.

Introduction
The topology for this deployment is divided into two major parts: 1. Production, or in-band 2. Out-of-band (OOB) Management The production topology contains redundant components and is used for all mission-critical and end-user network traffic. The OOB management network is an isolated network for remote management.
Production topology
The production topology that is used in this guide is shown in the figure below.

10

Topology

Figure 5. PowerFlex leaf-spine production topology
NOTE: PowerFlex on SONiC is supported with a leaf-spine BGP EVPN topology as shown in this guide. For a leaf and spine deployment, PowerFlex recommends a minimum of 3 spines. In this document, 4 spines are used. An access, aggregation, core topology may be supported in some cases. See Appendix A for more information.
Each rack has two leaf switches connected to each other with a multichassis link aggregation group (MC-LAG) peer link. Every leaf switch is connected to every spine switch to form a leaf-spine (also known as a Clos) topology.
NOTE: Leaf switches are sometimes called top-of-rack (ToR) switches.
In this deployment example, a three-node PowerFlex Management Controller (PFMC) 2.0 cluster is in Rack 1. The remaining nodes in Racks 1-n are compute only (CO) and storage only (SO) nodes. This deployment uses four 25 GbE network interface controller ports per PowerFlex node for production network connections, as shown in the figure above.
NOTE: The topology used to validate this guide consisted of four racks, eight leaf switches, four spine switches, and two external switches.
In this deployment example, Leaf1A and Leaf1B are border leafs which are connected to the external switches. The external switches are typically part of an existing network in the data center with DNS and NTP services and Internet or WAN access.
As an option, an additional leaf pair can be added as dedicated border leafs, with no compute or storage nodes connected to them. This option may be beneficial if there is a large amount of North-South traffic between the leaf-spine fabric and the external network. The dedicated border leaf pair must be configured as MC-LAG peers and connected to every spine switch like the other leaf switches in the fabric.
Uplinks from the border leaf switches to the external switches may be configured as Layer 2 or Layer 3. If Layer 3 uplinks are used, you may use Border Gateway Protocol (BGP), Open Shortest Path First (OSPF), or static routing. In the configuration example used in this guide, the uplinks are configured as Layer 3 with BGP.
NOTE: If an external network is not used, the required DNS and NTP services may be on a server that is connected directly to a leaf switch.

Equal-Cost Multi-Path routing (ECMP) is enabled on the switches to use all available bandwidth on the leaf-spine connections. Border Gateway Protocol (BGP) Ethernet VPN (EVPN) with Virtual Extensible LAN (VXLAN) is used to stretch Layer 2 networks across the Layer 3 leaf-spine fabric.
BGP EVPN with VXLAN overview
NOTE: If spines are not used in a single rack deployment, then BGP EVPN with VXLAN is not used.
For multirack deployments, BGP EVPN with VXLAN stretches virtual (overlay) Layer 2 networks across a physical (underlay) Layer 3 leaf-spine fabric. This architecture allows for the scalability of Layer 3 networks with the mobility benefits of a Layer 2 network. For example, a VM or physical host can be moved from one rack to another without changing its IP address and gateway information.
EVPN uses BGP to exchange endpoint MAC and IP address information between VXLAN tunnel endpoints (VTEPs). In this topology, each pair of leaf switches in a rack is one logical VTEP. Packets destined to a remote device are sent to the local VTEP as the first hop. The packet is encapsulated with a VXLAN header that includes the Virtual Network Identifier (VNI) and the IP address of the destination host. See the figure below.

Figure 6. VXLAN encapsulated frame
The destination VTEP extracts the original packet and routes it to the final destination. VXLAN encapsulation adds approximately 50 bytes of overhead to each Ethernet frame. As a result, all switches in the underlay (physical) network must be configured to support an MTU of at least 1600 bytes on all participating interfaces.
NOTE: In this deployment example, switch interfaces are set to their maximum supported MTU size of 9216 bytes for best performance. Anycast gateways with the same IP address are configured on each leaf pair. The anycast gateway IP address is set as the default gateway for all hosts and VMs on that virtual network. Hosts and VMs with anycast gateways use the same gateway information while behind different leaf pairs. This configuration replaces Virtual Router Redundancy Protocol (VRRP) and enables hosts and VMs to migrate from one leaf pair to another without changing the network configuration.

Each leaf switch has one connection to each spine switch. For this deployment, all leaf-spine connections are 100 GbE.
All PowerFlex nodes have two connections to each leaf. The connections in this example are 25 GbE. The four 25GbE connections from each PowerFlex node to the leaf switches are configured in two LACP link aggregation groups (LAGs).
For the MC-LAG peer link connections, two QSFP28-DD double density ports (2 x 100 GbE interfaces per physical port), are available on S5248F-ON switches. They are used to create a 400 GbE port channel that is the MC-LAG peer link. This connection requires QSFP28-DD DAC cables or optics. On switches without QSFP28-DD ports, QSFP28 100 GbE or SFP28 25 GbE ports are used for peer link connections. Dell Technologies recommends using at least two physical ports on each leaf switch for the peer link. This configuration is for redundancy and provides additional bandwidth if there is a failure. The peer link is used for data traffic only if there is a link failure that requires the peer link to reach the destination.

OOB management topology
The out-of-band (OOB) management network is an isolated network for remote management of hardware. This hardware includes PowerFlex nodes and PowerSwitch network switches. It can also include other devices using their dedicated management ports. One S3248T-ON switch is typically installed in each rack for OOB management network connections, as shown below.

Figure 8. OOB management network topology
The 1 GbE 1000BASE-T ports on each S3248T-ON are connected downstream to hardware management ports on each device in the rack. Those ports include the PowerSwitch management ports and PowerFlex node iDRAC ports. Dedicated management ports on other devices in the rack can also be connected. Four 10 GbE SFP+ ports are available on each S3248T-ON for use as uplinks to the OOB management network core and for downlinks to the 10 GbE OOB management NIC on the PFMC nodes. OOB management switch configuration is not detailed in this guide. The OOB management network can be Layer 2 or Layer 3, and can be configured to suit your environment.
NOTE: For reference, devices on the OOB Management network in this guide use the 100.67.0.0/16 IP address range. All addresses that are used in this guide are examples only.
OOB management connection details
All PowerSwitch management ports and PowerFlex node iDRACs are connected to the OOB management switch in each rack. Each PFMC node has two connections to the OOB management network: the 1 GbE iDRAC and an additional 10 GbE NIC, as shown in the figure below. PowerFlex Manager uses the PFMC node's 10 GbE to communicate with the iDRACs on the PowerFlex compute and storage nodes. The PowerFlex compute and storage nodes only require the iDRAC connection to the OOB network.

Minimum networking requirements
NOTE: In this guide, "single rack" means topologies with only two leaf switches. "Multirack" means topologies with four or more leaf switches.
The minimum networking requirements for a PowerFlex on Dell Technologies Enterprise SONiC deployment include the following: ● Single rack deployments require two supported Dell PowerSwitch leaf switches of the same model.
NOTE: If a future expansion from a single to a multirack topology is likely, Dell Technologies recommends installing and configuring two supported Dell PowerSwitch spine switches. Doing so will simplify the expansion process in the future.
● Multirack deployments require two supported Dell PowerSwitch leaf switches of the same model per rack, plus at least two supported Dell PowerSwitch spine switches.
● All Dell PowerSwitch leaf and spine systems in fabric must be running the same version of Dell Technologies Enterprise SONiC.
● Dell Technologies Enterprise SONiC 4.1.1 or later is required. An Enterprise Standard or Enterprise Premium bundle is required for this deployment.
● One 1 GbE BASE-T switch for OOB management connections is required. Dell Technologies recommends using one PowerSwitch S3248T-ON per rack.
● One DNS server and one NTP server that are reachable from the PowerFlex Node Management network are required. ● Each PowerFlex node requires four 25 GbE SFP28 connections to the leaf switches. ● Each leaf to spine connection requires at least one 100 GbE QSFP28 connection. Provide enough connections to ensure the
oversubscription ratio at the leaf switches does not exceed 2:1. ● MC-LAG peer links between leaf switch pairs require at least two connections for fault tolerance. Each link can be 25 GbE
SFP28, 100 GbE QSFP28, or 200 GbE QSFP28-DD (available on S5248F-ON). If 25 GbE ports are used, Dell recommends using at least four connections for sufficient bandwidth if a switch is taken offline. ● One 1 GbE (1000BASE-T) connection is required for each switch OOB management port. ● One 1 GbE (1000BASE-T) connection is required for each PowerFlex node iDRAC port. ● One 10 GbE connection is required for each PFMC node to access the OOB management network in addition to the PFMC node's 1 GbE iDRAC port. NOTE: See your PowerFlex documentation for minimum PowerFlex node requirements.
Maximum deployment size
The maximum number of switches and nodes that are supported for PowerFlex on SONiC deployments are: ● Spine switches—6 ● Leaf switches—32 ● PowerFlex nodes—352 (22 nodes per leaf pair)

Loopback addresses and BGP ASNs

Loopback addresses are configured on leaf and spine switches for use as router IDs and VTEP addresses. Autonomous System Numbers (ASNs) are configured on the switches for use with Border Gateway Protocol (BGP).
Each leaf or spine switch must have a unique router ID. Each leaf pair shares a VTEP IP address, and an ASN. Spines do not have VTEP addresses, and all spines in the fabric share the same ASN. The external switches are also configured for BGP in this example. They each have unique router IDs and share an ASN that is different from the leaf and spine ASNs.

General settings

About this task Perform these steps to configure general settings on Leaf1A and Leaf1B:

Steps

Introduction
Dell Technologies recommends that you use the leaf-spine production topology covered in this guide. A leaf-spine topology is the standard data center architecture, is designed to optimize performance, and is highly scalable. However, in smaller deployments, some customers might prefer to use an access-aggregation production topology, where the aggregation switches terminate all Layer 2 traffic from the PowerFlex cluster and connect to core switches for North-South communication. The supported access-aggregation topology for multirack PowerFlex deployments is shown in the figure below.

Using an access-aggregation topology with PowerFlex

Figure 10. Access-aggregation topology for multirack PowerFlex deployments
NOTE: The OOB management topology shown in this guide is the same for access-aggregation and leaf-spine production topologies.
Access-aggregation topology networking requirements
Requirements for PowerFlex on SONiC access-aggregation topology include the following: NOTE: "Single rack" refers to topologies with only two access switches. "Multirack" refers to topologies with four or more access switches.
● All access and aggregation switches must be running the same version of Dell Enterprise SONiC, and it must be 4.2.0 or later. An Enterprise Standard or Enterprise Premium bundle is required.

48

Using an access-aggregation topology with PowerFlex

● Single rack deployments require two supported Dell PowerSwitch access switches. S5212F-ON, S5224F-ON, and S5248FON are supported as access switches.
● Multirack deployments require two supported Dell PowerSwitch access switches per rack, plus two supported Dell PowerSwitch aggregation switches. S5232F-ON is supported as an aggregation switch.
● Access and aggregation switches must be deployed in pairs and be configured for MC-LAG. Each switch in an MC-LAG pair must be the same model.
● In multirack deployments, all access switches connected to PowerFlex nodes must be connected to the same pair of aggregation switches.
● If aggregation switches have uplinks to core switches, PowerFlex data traffic must not pass through the core switches. ● Each access-to-aggregation switch connection must be at least 100 GbE, Layer 2, and be configured for LACP. Provide
enough connections to ensure the oversubscription ratio at the access switches does not exceed 2:1. ● MC-LAG peer links between access and aggregation switch pairs require at least two connections for fault tolerance. Each
access switch peer link can be 25 GbE SFP28, 100 GbE QSFP28, or 200 GbE QSFP28-DD (available on S5248F-ON). If 25 GbE ports are used, Dell Technologies recommends using at least four connections for sufficient bandwidth if a switch is taken offline. Each aggregation switch peer link must be at least 100 GbE. ● Each PowerFlex node requires four 25 GbE SFP28 connections to the access switches. LACP is recommended on these connections, but it is not required. ● One 1 GbE (1000BASE-T) switch for OOB management connections is required. Dell Technologies recommends using one PowerSwitch S3248T-ON per rack. ● One 1 GbE (1000BASE-T) connection is required for each switch OOB management port. ● One 1 GbE (1000BASE-T) connection is required for each PowerFlex node iDRAC port. ● One 10 GbE connection is required for each PFMC node to access the OOB management network in addition to the PFMC node's 1 GbE iDRAC port. ● One DNS server and one NTP server that are reachable from the PowerFlex Node Management network are required.
