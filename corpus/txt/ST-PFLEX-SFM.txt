Introduction
This deployment guide covers Dell Technologies PowerSwitch configuration using SmartFabric Manager for SONiC (SFM) for single rack or multirack greenfield PowerFlex deployments.
SFM automates the configuration of the leaf-spine fabric that is used in this deployment. The leaf-spine fabric uses EVPN VXLAN, which enables a virtual Layer 2 overlay network to run over a physical Layer 3 underlay network. Use of a VXLAN leaf-spine fabric is a best practice in the data center.
Enterprise SONiC Distribution by Dell Technologies
SONiC is an open-source, Linux-based network operating system that runs on switches from multiple vendors and ASICs. Enterprise SONiC Distribution by Dell Technologies is a hardened and validated version of SONiC that is supported on certain Dell PowerSwitch platforms. Dell Enterprise SONiC supports an intuitive command-line interface, object-based administration through a REST interface, Google’s gRPC Network Management Interface (gNMI), and SmartFabric Manager.
SmartFabric Manager for SONiC
SmartFabric Manager for SONiC (SFM) simplifies network setup and maintenance by automating network deployment and providing an easy-to-use web user interface.
SFM is a virtual machine that runs on VMware ESXi, provided in OVA format, or on Linux KVM, provided in QCOW2 format. SFM configures Dell PowerSwitch systems using REST API commands and offers customizable blueprints to simplify configuration for different solutions, including PowerFlex.
The PowerFlex deployment in this guide uses a Border Gateway Protocol (BGP) Ethernet VPN (EVPN) with Virtual Extensible LAN (VXLAN) leaf-spine fabric. Use of a VXLAN leaf-spine fabric is a best practice in the data center. Manually configuring the switches for this fabric would require hundreds of CLI commands. SFM automates the fabric creation, making it fast, easy, and with a much lower probability of errors than configuring the fabric manually.
SFM comes with a 180-day free trial for up to 10 switches. If your PowerFlex deployment uses more than 10 switches in leaf or spine roles, you must buy a license before proceeding. See the SFM User Guide for more information about licensing.
PowerFlex
PowerFlex is a highly scalable compute and storage infrastructure that integrates PowerFlex software-defined storage software with Dell PowerEdge servers. PowerFlex supports a small cluster starting point of four nodes, bring-your-own networking hardware, and bring-your-own management hardware.
PowerFlex allows growth and management of compute and storage resources together or independently depending on business needs. PowerFlex uses PowerFlex Manager for management and operations. PowerFlex Manager enables users to build, automate, and simplify implementation, expansion, and life cycle management.
This deployment uses PowerFlex partial network automation (PNA). With PNA, PowerFlex manager automatically configures the VLANs and IP addresses on the PowerFlex nodes, but it does not configure the switches.

Topology
The topology for this deployment is divided into two parts:
1. Production, or in-band 2. Out-of-band (OOB) management
The production topology contains redundant components and is used for all mission-critical and end-user network traffic. The OOB management network is an isolated network for hardware management.
Production topology
The production topology that is used in this guide is shown in the figure below.

PowerFlex leaf-spine production topology

Each rack has two leaf switches connected to each other with a multichassis link aggregation group (MCLAG) peer link. Downlinks from leaf switches to devices in the rack use LACP with MC-LAG. Every leaf switch is connected to every spine switch to form a leaf-spine topology.
Note: Leaf switches are sometimes called top-of-rack (ToR) switches.
In this deployment example, a three-node PowerFlex Management Controller (PFMC) 2.0 cluster is in Rack 1. The remaining nodes in Racks 1-n are compute only (CO) and storage only (SO) nodes. This deployment uses four 25 GbE network adapter ports per PowerFlex node for production network connections, as shown in the figure above.
Note: The topology used to validate this guide consisted of four racks, eight leaf switches, and four spine switches.
BGP EVPN with VXLAN is used to stretch Layer 2 networks across the Layer 3 leaf-spine fabric. Equal-Cost Multi-Path routing (ECMP) is enabled on the switches to use all available bandwidth on the leaf-spine connections. SFM automates the configuration of this fabric.
The DNS/NTP server that is used for PowerFlex name resolution and time synchronization can be located anywhere that is reachable from the PowerFlex Node Management network. In this example, it is in Rack 1 and has one connection to each leaf in the rack for redundancy.

For the MC-LAG peer link connections, two QSFP28-DD double density ports (2x 100 GbE interfaces per physical port), are available on S5248F-ON switches. They are used to create a 400 GbE port channel that is the MC-LAG peer link. This connection requires QSFP28-DD DAC cables or optics.
Note: On leaf switches without QSFP28-DD ports, QSFP28 100 GbE or SFP28 25 GbE ports are used for peer link connections. Dell Technologies recommends using at least two physical ports on each leaf switch for the peer link. If 25 GbE ports are used, Dell Technologies recommends using at least four connections on each leaf for sufficient bandwidth. Multiple peer link connections provide redundancy and additional bandwidth if a switch is taken offline or if there is a failure. The peer link is used for data traffic only if there is a link failure that requires the peer link to reach the destination.
OOB management topology
The out-of-band (OOB) management network is an isolated network for remote management of hardware. This hardware includes PowerFlex nodes and PowerSwitch systems. It can also include other devices using their dedicated management ports.
One S3248T-ON switch is typically installed in each rack for OOB management network connections, as shown in the following figure. Other Dell or third-party switches with 1 GbE BASE-T ports can also be used for OOB management traffic.

Four 10 GbE SFP+ ports are available on each S3248T-ON. These ports are typically used as downlinks to a 10 GbE NIC on each PFMC node and as uplinks to the OOB management network core. There are also two 100 GbE QSFP28 ports available on each S3248T-ON if needed.

Deployment Planning
This chapter covers items to consider before deploying a PowerFlex network with SFM.
Minimum networking requirements
Note: In this guide, “single rack” means topologies with only two leaf switches. “Multirack” means topologies with four or more leaf switches.
The minimum networking requirements for a PowerFlex on Dell Technologies Enterprise SONiC deployment with SFM include the following:
• SFM version 1.2 or later. SFM comes with a 180-day free trial for up to 10 switches. If your PowerFlex deployment uses more than 10 switches in leaf or spine roles, you must purchase a license before proceeding. See the SFM User Guide for more information about licensing.
• Single rack deployments require two supported Dell PowerSwitch leaf switches of the same model. • Multirack deployments require two supported Dell PowerSwitch leaf switches of the same model per
rack, plus at least two supported Dell PowerSwitch spine switches.
Note: For a new deployment that is done using the SFM PowerFlex blueprint as shown in this guide, all leaf switches in the initial fabric must be the same model. All spine switches in the initial fabric must also be the same model. The fabric can later be expanded using other supported PowerSwitch models.
• All Dell PowerSwitch leaf and spine systems in the fabric must be running the same version of Dell Technologies Enterprise SONiC.
• Dell Technologies Enterprise SONiC 4.4.1 or later is required. An Enterprise Standard or Enterprise Premium bundle is required for leaf and spine switches in this deployment.
• One 1 GbE BASE-T switch for OOB management connections is required. Dell Technologies recommends using one PowerSwitch S3248T-ON per rack.
• One DNS server and one NTP server that are reachable from the PowerFlex Node Management network are required.
• Each PowerFlex node requires four 25 GbE SFP28 connections to the leaf switches. • Each leaf to spine connection requires at least one 100 GbE QSFP28 connection. Provide enough
connections to ensure that the oversubscription ratio at the leaf switches does not exceed 2:1. • MC-LAG peer links between leaf switch pairs require at least two connections for fault tolerance.
Each link can be 25 GbE SFP28, 100 GbE QSFP28, or 200 GbE QSFP28-DD (available on S5248FON). If 25 GbE ports are used, Dell Technologies recommends using at least four connections for sufficient bandwidth. • One 1 GbE (1000BASE-T) connection is required for each switch OOB management port. • One 1 GbE (1000BASE-T) connection is required for each PowerFlex node iDRAC port. • One 10 GbE or faster connection is required for each PFMC node to access the OOB management network in addition to the PFMC node's 1 GbE iDRAC port. • On server running ESXi 7.0 or later or Linux KVM to host the SFM VM. The server must have at least one network connection that can reach the OOB management network. This connection is used for SFM to communicate with the leaf and spine switches. The SFM VM requires 32 GB RAM, 120 GB free disk space, and 16 virtual CPUs.
Note: See your PowerFlex documentation for additional PowerFlex node requirements.

5.1

Prepare switches for SFM
Dell PowerSwitch systems that are used in leaf or spine roles in this deployment must be running Dell Technologies Enterprise SONiC 4.4.1 or later. An Enterprise Standard or Enterprise Premium bundle is required.

5.1.1

Set a password and configure the management interface
For each Dell PowerSwitch that will be a leaf or a spine in the fabric, do the following:
1. Connect to the switch using the console serial port. 2. Log in to the CLI as admin. 3. Change the admin password from the default, YourPaSsWoRd, to a secure password during the first
login when prompted. 4. Configure the OOB management interface, named Management 0.
SFM uses the management interface to communicate with the leaf and spine switches. For SFM, Dell Technologies recommends using a static IP address instead of DHCP on Management 0 to ensure that it does not change. Use a unique IP address on each switch. If routing is used on your OOB management network, also specify the gateway address as shown in the configuration example below.
admin@sonic:~$ sonic-cli sonic# configure sonic(config)# interface Management 0 sonic(config-if-Management0)# ip address 100.67.100.189/24 gwaddr 100.67.100.254 sonic(config-if-Management0)# end sonic# write memory

Note: If any leaf or spine switches have previously been configured (other than changing the admin password and configuring Management 0), run the write erase command and reboot each applicable switch. The admin password and Management 0 interface configuration are retained. All other configuration settings on the switch are reset to the factory defaults. The switches must be in this state for the SFM blueprint to be applied successfully.

5.1.2

Connect the switches and SFM host
Make the switch and SFM host connections as shown in Production network connection details and OOB management network connection details. The PowerFlex nodes do not have to be connected now.

The host must have network connectivity to the OOB management network so that SFM can communicate with the leaf and spine switches. Example network connections are shown in OOB management network connection details.

B BGP EVPN with VXLAN overview
BGP EVPN with VXLAN stretches virtual (overlay) Layer 2 networks across a physical (underlay) Layer 3 leaf-spine fabric. This architecture allows for the scalability of Layer 3 networks with the mobility benefits of a Layer 2 network. For example, a VM or physical host can be moved from one rack to another without the need to change its IP address and gateway information. All paths in the VXLAN fabric are active, and the spanning tree protocol does not block any paths. SFM automates the configuration of the VXLAN fabric.
EVPN uses BGP to exchange endpoint MAC and IP address information between VXLAN tunnel endpoints (VTEPs). In this topology, each pair of leaf switches in a rack is one logical VTEP. Packets destined to a remote device are sent to the local VTEP as the first hop. The packet is encapsulated with a VXLAN header that includes the Virtual Network Identifier (VNI) and the IP address of the destination host. See the figure below.

VXLAN encapsulated frame
The destination VTEP extracts the original packet and routes it to the destination. VXLAN encapsulation adds approximately 50 bytes of overhead to each Ethernet frame. As a result, all switches in the underlay (physical) network must be configured to support an MTU of at least 1600 bytes on all participating interfaces.
Note: In this deployment example, switch interfaces are set to their maximum supported MTU size of 9216 bytes for best performance.
Anycast gateways with the same IP address are configured on each leaf pair. The anycast gateway IP address is set as the default gateway for all hosts and VMs on that virtual network. Hosts and VMs with anycast gateways use the same gateway information while behind different leaf pairs. This configuration replaces the Virtual Router Redundancy Protocol (VRRP) and enables hosts and VMs to migrate from one leaf pair to another without changing the network configuration.
